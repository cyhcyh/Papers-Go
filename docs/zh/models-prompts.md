# 模型配置

[目录](index.md) · [English](../en/models-prompts.md)

首次使用先完成“模型连接”和“功能分配”。Prompts 和 Skills 可保持默认，等基础流程跑通后再调整。

入口：后台 → 模型配置。四个子标签为 **模型连接、功能分配、Prompts、Skills**。

## 一、添加云端连接

1. 在“模型连接”点击“添加连接”，选择云端类型。
2. 名称填写方便自己识别的名字，例如“我的云端服务”。
3. Base URL 填服务商提供的 OpenAI 兼容接口地址。例如百炼兼容地址为 `https://dashscope.aliyuncs.com/compatible-mode/v1`。其他服务商使用其自己的地址。
4. API Key 填对应平台创建的密钥，不填账号密码。
5. 保存连接，再使用连接卡片提供的测试 / 更新可用模型操作。
6. 确认可用模型列表已出现，然后到“功能分配”选择模型。

![模型连接](../images/model-links.jpg)

部分服务不提供完整模型目录，此时可按服务商给出的准确模型 ID 填写，并通过实际调用核实。

## 二、添加本地 Ollama

1. 确认 Ollama 已启动，并已准备需要的生成模型或向量模型。
2. 添加连接，类型选“本地 Ollama”。
3. 按部署位置填写地址：

| 部署位置 | 地址 |
| --- | --- |
| Ollama 与网站在同一 Compose 网络 | `http://ollama:11434` |
| Ollama 在 Docker 宿主机 | `http://host.docker.internal:11434` |
| 后端和 Ollama 都直接运行在本机 | `http://localhost:11434` |

4. 保存并更新可用模型。
5. 对照模型目录选择模型，注意完整名称和标签。

网页能访问本机 Ollama，不代表 Docker 容器也能访问。无法连接时先核对地址、监听接口和防火墙。模型下载由您在 Ollama 中管理。

## 三、添加 Codex 连接

Codex 连接通过设备码登录自己的 ChatGPT 账户，无需填写 API Key，也无需在部署机器上安装 Codex CLI。

1. 在“模型连接”点击“添加连接”，类型选择“Codex”。
2. 填写连接名称，例如“我的 Codex”。服务地址使用默认的“Codex 服务（设备码流程）”。
3. “兼容版本更新”保持“自动检测官方稳定版本”，OAuth 高级配置中的 Client ID 保留默认值，保存连接。
4. 在连接卡片上点击“登录 Codex”，查看设备码，点击“授权页面”链接。
5. 在授权页面登录自己的 ChatGPT 账户，输入设备码并确认授权。
6. 回到模型配置页。页面会自动检查授权状态，显示“已登录 ChatGPT”后自动更新可用模型。需要手动刷新时，点击“更新可用模型”。
7. 打开“功能分配”，选择需要使用 Codex 的功能，将连接设为刚添加的 Codex 连接，再选择模型并保存。

可用模型和额度取决于所授权账户。网站后端也需要能访问授权和模型服务；浏览器完成登录后，若模型目录仍加载失败，查看连接卡片上的错误信息。

### 授权管理

- 设备码过期：重新点击“登录 Codex”，使用新的设备码授权。
- 更换账户或恢复授权：点击“重新授权”，在授权页面使用需要的账户完成登录。
- 解除网站授权：点击“退出授权”，网站会清除该连接保存的授权凭据。下次使用前需重新登录。

### 兼容版本与向量模型

自动检测会在更新可用模型时检查兼容版本。版本变化后，网站会验证实际流式回复，通过后再采用；验证失败时保留原有可用版本和模型目录。需要指定版本时，在连接编辑页改为“手动指定版本”并填写版本号。

Codex 连接用于文本生成，不提供本站所需的 embedding 服务。“向量生成”请另行分配云端或 Ollama 的向量模型；主题分类、兴趣推荐和语义检索仍需要这项配置。

## 四、为每个功能分配模型

打开“功能分配”，找到目标功能，打开配置，选择连接和模型并保存。同一个连接可供多个功能使用。

| 功能 | 第一次怎样设置 | 何时会调用 |
| --- | --- | --- |
| 向量生成 | 选择 embedding 模型，维度与服务能力一致 | 论文向量、兴趣更新和检索 |
| 主题分类 | 选择能稳定返回结构化结果的文本模型 | 分类任务及相关提议 |
| 质量与新颖性评估 | 选择文本模型 | 论文质量评估任务 |
| 中文标题与论文速读 | 选择文本模型 | 生成标题翻译及两项速读 |
| 智能助手 | 选择支持工具调用的聊天模型 | 前台对话 |
| 上下文压缩 | 按需独立分配 | 长对话整理 |
| 论文精读 / 深度解析 | 分别选择能处理长文的模型 | 论文精读 / 深度解析请求 |
| 兴趣描述整理 | 按需分配 | 兴趣描述整理调用 |
| 每周画像反思 | 按需分配 | 根据最近行为整理兴趣 |
| 方向趋势简述 | 选择文本模型 | 个人研究趋势生成 |
| 分类抽样评估 | 按需分配 | 分类抽查任务 |

**向量模型与聊天模型不同。**如果当前云端连接只有聊天模型，需要额外添加 embedding 服务或本地向量模型。只配好智能助手，不会自动配好分类、速读或精读。

支持备用模型的功能可以配置备用连接与模型。初次先验证主模型，再增加备用，便于定位错误。

![功能分配](../images/model-settings.jpg)

### 思考模式和推理强度

在对应功能的高级设置中选择自动、开启或关闭思考，以及模型支持的推理强度。显示的选项取决于目录和已确认的能力；不是每个模型都支持关闭思考。

第一次保留自动。若调整后报参数不支持，先恢复自动，再检查该模型与服务商的能力。隐藏思考文本只影响页面展示，不等于服务端没有思考或没有消耗相关 token。

### 并发设置

| 功能 | 默认值 | 后台范围 |
| --- | --- | --- |
| 云端 / Codex 主题分类 | 4 | 1～16 |
| 云端 / Codex 论文速读 | 4 | 1～8 |
| 云端 / Codex 质量评估 | 2 | 1～8 |
| 云端 / Codex 共享精读队列 | 2 | 1～8 |
| 本地共享精读队列 | 1 | 1～4 |

先用默认值，确认服务额度、显存和响应稳定后再提高。本地分类、速读等还受本地模型资源调度约束，增大某个队列参数不保证实际吞吐线性增加。

### 更换向量模型

已经生成向量后，更换模型、服务地址或维度会改变向量空间。使用页面提供的安排重建流程；完成验证和切换后才使用新空间，失败或停止时保留原模型和原向量。不要只把旧向量当作新模型的结果继续使用。

## 五、调整 Prompts

1. 打开 Prompts，选择功能。
2. 查看当前指令与默认内容。
3. 修改表达风格、关注重点或篇幅，保留界面说明中的结构要求。
4. 保存，用少量论文或一次新对话验证。
5. 不满意时使用默认内容恢复；已有论文结果需重做才会改变。

| 想改什么 | 指令位置 |
| --- | --- |
| 中文译名与两项速读 | `brief`、`brief_compact` |
| 六问精读 | `reading_card`，长文材料整理见 `reading_section` |
| 趋势内容与表达 | `trend_report`、`trend_rewrite` |
| 智能助手 | `chat` |
| 分类及新主题提议 | `classify`、`topic_proposal` |

后台修改保存在数据库，不改写默认源码文件。需要查阅默认值时，见 `backend/app/prompts.toml`。质量评估的系统指令在 Skills 中维护，参见[智能助手与 Skills](assistant.md)。

## 六、凭据保存

API Key 和 Codex 授权加密保存，页面不会回显明文。留空的密钥输入通常保留已有密钥；需要移除时使用明确的清除操作。恢复数据库时必须同时恢复原加密密钥，详见[运行维护](maintenance.md)。
