# 常见问题

[目录](index.md) · [English](../en/faq.md)

## 网站打不开，怎么办？

在部署目录执行 `docker compose ps`，确认 Docker 正常、`app` 启动且端口未占用。再执行 `docker compose logs --tail=100 app worker`。默认地址是 `http://localhost:8000`；修改宿主机端口后使用实际端口。局域网其他设备使用部署主机 IP，不能用它们自己的 localhost。

## 刚安装好，为什么首页没有论文？

新安装没有预先登记的抓取来源。先到“分类与来源”添加分类并开启自动抓取，再到任务中心运行 arXiv 或顶会任务。游客还需要来源勾选游客默认。登录用户检查自己的分类、主题和时间筛选。只配置模型不会自动出现论文。

## 没有管理员默认账号吗？

没有。第一个注册账号自动成为管理员，后续注册默认是普通用户。首次注册成功时请保存随机生成的后台入口。

## 忘记了后台入口怎么办？

如果另有管理员能够进入后台，请其从“基本设置”查看。若仍有打开的后台页面，也可在那里查看或修改。不要新建普通账号期待再次获得首次管理员权限。没有可用入口时应由部署维护者根据备份或站点配置恢复，避免删除数据库重新初始化。

## API Key 填了，为什么任务还显示待配置？

连接信息和功能分配是两步。在“模型连接”保存凭据后，还要到“功能分配”为每个功能选择连接和模型。主题分类同时依赖分类模型与向量模型。按错误提示补齐对应项。

## 为什么聊天模型能对话，却不能建立向量？

embedding 使用不同的接口和模型。选择真正的向量模型，并设置服务支持的维度。若服务仅提供聊天模型，另接向量服务或 Ollama 向量模型。

## Docker 为什么连不上本机 Ollama？

容器内 localhost 是容器自己。宿主机 Ollama 通常使用 `http://host.docker.internal:11434`，同一 Compose 的 Ollama 使用 `http://ollama:11434`。还需确认服务监听允许容器访问、端口可达且已安装模型。

## 抓取一直运行，是卡住了吗？

看已处理数是否增长，并查看详细来源日志。正常 arXiv 同步会分页处理未同步的日期窗口，分类多、初次缺口大或遇到限流都会延长。首次试运行的 `FETCH_LIMIT` 不是日常同步上限。会议通常只同步最新届次；来源响应慢也会等待。需要暂停时使用任务停止按钮。

## 已抓到论文，为什么没有中文标题和速读？

抓取只保存原始信息。需要运行“论文速读”，它会生成中文译名、“研究问题”“主要贡献和结果”。检查该功能模型配置及失败项目。

## 分类树为什么没有研究主题？

研究方向目录不等于正式主题。到“主题管理”批准提议或直接添加，再检查论文分类。只运行抓取不产生主题；主题被停用也会移除论文标签。

## 改主题名字，论文标签会一起改吗？

会。论文关联主题 ID，重新加载后显示当前名称。若改的是方向含义，应检查是否需要重新分类；仅改名字不需要逐篇重新生成标签。

## 删除主题会删论文吗？删除分类呢？

停用或彻底删除主题保留论文，移除或调整主题引用。删除来源分类会按预览清理独属该来源的论文；仍有其他保留来源的论文留下。两种操作影响不同，先阅读确认弹窗。

## 更新兴趣后首页似乎没变化？

先看兴趣更新状态是否完成。保存表单后还要生成兴趣向量。确认所选来源有论文，正式主题已批准，临时兴趣未过期；如果原候选论文已符合新兴趣，结果也可能相近。

## 论文显示过，为什么“今日已刷”没增加？

首页卡片需在可见区域连续停留约 5 秒才记录。加载到列表或快速划过不算。查看的是当前账号、当前站点时区的统计。

## 精读为什么要排队，关闭页面会取消吗？

精读共享并发有限，页面显示同类等待队列前方人数。关闭页面不取消已接受任务。同一论文会复用任务和缓存。worker 重启可恢复等待队列，但正在调用模型的中断任务需重试。

## 为什么模型思考没有百分比？

服务没有提供可靠的总思考量，系统只显示状态、用时及已经生成的问题。隐藏思考内容不代表后台没有工作。

## 修改 Prompt 后旧精读卡为什么没变？

已有缓存不会因指令编辑自动全部重生成。用新调用验证指令后，管理员按需重做速读、精读等结果。重做会消耗模型资源。

## 趋势页为什么没有热点或没有我的方向？

检查兴趣是否有效、本期公告是否有匹配新稿、分类及主题审批是否完成。热点至少需要同一主题 3 篇新稿；没有热点不等于没有论文。“趋势聚合”只生成统计，文字解读由“方向趋势简述”生成。

## 关闭任务计划后，为什么精读还会继续？

定时计划、流水线启用开关和用户精读队列是不同机制。用户已提交的精读由 worker 持续处理；关闭定时调度不等于停止所有后台队列。

## 日志保留 30 天，是每 30 天要重填 API Key 吗？

不是。期限针对日志。凭据加密保存在数据库，原密钥不变且服务商未使其失效时可以继续使用。备份应同时保存 `data/` 与 `.secrets/`。

## 没有服务器，可以在 GitHub 上运行整个系统吗？

GitHub Pages 可以展示使用文档，不能承载本系统的 Python API、数据库和常驻 worker。您可以继续在自己电脑通过 Docker 使用系统，并把双语文档放在 GitHub 阅读或发布成静态站点。见[文档维护与发布](publishing.md)。
