# 任务中心

[目录](index.md) · [English](../en/pipeline.md)

入口：后台 → 任务中心。本页处理论文抓取和加工，用户浏览网页不需要等待整条流水线结束。

## 第一次怎样运行

按[快速开始](quick-start.md)完成来源与模型配置后，点击页面顶部的“运行完整流水线”。系统会按顺序执行所有启用的步骤，无需逐项手动启动。

流水线启动前会检查启用步骤所需的模型配置。提示缺少配置时，到“模型配置 → 功能分配”补齐；不需要的步骤可以禁用，后续执行时会跳过。

运行期间可查看各任务状态和处理数量，已经处理好的论文可以直接浏览。主题分类产生的新主题提议，在“主题管理”中审核。

完整流水线不包含下方的独立任务。需要补做某一项或排查问题时，可在对应任务卡片上点击“现在运行”。

## 各个流水线步骤做什么

| 页面名称 / 标识 | 做什么 | 主要实现 |
| --- | --- | --- |
| arXiv / `fetch_arxiv` | 收录新增与更新论文 | 官方 Atom API，分类和时间窗口分页，按 ID、版本去重；维护同步进度 |
| 顶会论文 / `fetch_conf` | 收录会议最新一届论文 | papers.cool feed，最新届次检查、内容同步和缓存，保留真实标题、会议来源 |
| 社区信号 / `fetch_community` | 更新外部关注信号 | 获取 Hugging Face 点赞与相关 GitHub stars，复用缓存 |
| 主题分类 / `classify` | 选择唯一最相关主题 | 候选研究方向检索加模型决策；新方向走提议批准流程 |
| 建立向量 / `build_vectors` | 生成论文与兴趣向量 | embedding 服务，统一向量空间和检索索引 |
| 论文质量评估 / `assess_quality` | 生成参考质量分 | 评分技能分析摘要或缓存全文片段，结合贡献、会议、作者与社区信号 |
| 论文速读 / `tldr_gen` | 生成译名和两项解读 | 结构化模型输出、校验并逐篇保存 |
| Top 5 预读 / `preread` | 提前生成精读卡 | 为全库质量分最高的 5 篇请求精读，已有卡片复用 |
| 趋势聚合 / `trend_stats` | 计算主题统计 | 按主题和日期汇总数量、平均质量，不调用模型 |
| 预警评估 / `alert_eval` | 产生匹配通知 | 分批检查监视项与研究方向，保存增量状态 |
| 每日指标汇总 / `metrics` | 更新阅读统计 | 汇总浏览、喜欢、收藏、跳过、展开等事件 |

向量、速读和精读结果为共享论文加工结果，不为每位用户从头重新生成一份。个人推荐使用自己的兴趣和反馈。

## 独立任务

| 页面名称 / 标识 | 用途与实现 |
| --- | --- |
| 作者影响力 / `author_impact` | 从 OpenAlex 识别作者并缓存高被引相关信号，供质量和推荐使用；受外部额度限制时保留进度续跑 |
| 到期论文清退 / `paper_expiry` | 分批删除到期论文和关联数据，正在排队或生成的论文暂缓清退 |
| 方向趋势简述 / `trend_report` | 准备最新 arXiv 公告及必要分类，为近期活跃用户生成研究发展概述并复用缓存 |
| 画像反思 / `reflect` | 根据最近 7 天行为更新兴趣画像，没有新行为时跳过 |
| 分类抽样评估 / `audit` | 模型抽查分类并记录结果，按既有规则处理相关未归类论文 |

这些任务按各自计划运行，也可单独手动触发。独立任务“方向趋势简述”可能先准备公告和分类，所以并非只执行一次文本生成。

## 运行、停止和禁用

| 按钮 | 用途 |
| --- | --- |
| 现在运行 | 手动提交该任务，须已启用且 worker 就绪 |
| 停止 / 取消排队 | 停止对应运行或等待中的任务 |
| 停止当前任务 | 停止当前整组流水线工作 |
| 禁用 | 后续走到该步骤时跳过，也不能直接手动运行 |
| 启用 | 允许后续执行，不等于立即开始 |

希望当前正在运行的工作停下来时使用停止；仅关闭启用开关不能代替对正在执行调用的停止操作。已处理成功的论文结果保留。

## 计划任务设置

1. 点击“计划任务设置”。
2. 为完整流水线或独立任务开启计划。
3. 选择每日 / 每周、执行时间及星期。
4. 保存并核对下次触发时间和时区。

默认完整流水线每天 10:00、作者影响力 06:20、清退 11:00、方向趋势 10:50；画像反思每周日 04:00、分类抽样每周日 06:00。默认时区为 `Asia/Shanghai`，以您后台显示和保存的计划为准。

调度开关、任务启用状态和配置检查都会影响是否运行。服务未运行时无法按计划执行。

## 重做已有结果

支持重做的任务包括主题分类、建立向量、质量评估、论文速读和预读。使用任务卡片的重做入口，按弹窗选择范围，再确认。

适合重做的情况：更换生成模型、修改指令、纠正分类，或需要更新一批旧结果。日常新增论文通常不用全量重做。

结果按**每篇论文、每个处理项**替换：成功项保留新结果；失败或停止时保留该项原结果。它不是把整个任务的成功结果一起回滚。中途停止后检查已完成、失败和待处理项目，再使用页面提供的继续或重试操作。

向量模型整体更换还涉及向量空间重建与切换，应通过[模型配置](models-prompts.md)中的专用流程处理。

## 高级参数与排错

社区信号可设置 GitHub 凭据、查询时间范围和缓存；作者影响力可设置 OpenAlex 凭据、批次及缓存；分类抽样可设样本量；清退可设批次和保留期限。首次先保留默认。

显示“待配置”先补模型，“worker 未就绪”先检查工作进程；有失败论文时查看任务重试状态和日志。抓取耗时受来源数量、未同步窗口和外部限流影响，不是固定每天若干分钟。
